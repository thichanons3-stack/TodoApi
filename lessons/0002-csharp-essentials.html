บทที่ 2 จาก 6 · Controller-based vs Minimal API

C# ที่ต้องรู้ เพื่ออ่านโค้ดตัวเองออก

คุณเขียน TodoItemsController ได้แล้ว — แต่ถ้าอ่านออกเสียงทีละบรรทัดไม่ได้ เวลาจะตัดสินใจเรื่อง Controller vs Minimal API ก็จะตัดสินใจแบบลอยๆ บทนี้แกะ 5 โครงสร้าง C# ที่ปรากฏในไฟล์คุณอยู่แล้ว ให้ออกมาเป็นภาษาไทย — เสร็จแล้วคุณจะอ่านไฟล์ตัวเองได้ทุกบรรทัด

เป้าหมายบทนี้

เปิด Controllers/TodoItemsController.cs ค้างไว้ข้างๆ แล้วอ่านทีละบรรทัดไปด้วยกัน จบบทนี้คุณจะแปลง signature ของเมธอดได้ทั้งบรรทัดเป็นภาษาไทย

1 · Generics — ปลอกที่ใส่ "ชนิดข้อมูล" เป็นพารามิเตอร์

เจอในไฟล์คุณเต็มไปหมด: DbSet<TodoItem>, List<TodoItem>, Task<ActionResult<TodoItemDTO>> — ทุกตัวใช้แนวคิดเดียวกัน 

// จาก Data/TodoDb.cs — ปลอก DbSet ใส่ชนิด TodoItem เข้าไป
public DbSet<TodoItem> TodoItems => Set<TodoItem>();

// อ่านแบบนี้: " DbSet ที่เก็บ TodoItem " — พอใส่ชนิดเข้าไป compiler จะรู้ทันที
// ว่าห้าม Add() สิ่งอื่นที่ไม่ใช่ TodoItem เข้าไป ← ตัวอย่างสิ่งที่ generics ป้องกัน

ทำไมถึงสำคัญ: generics ทำให้ compiler รู้ "ชนิดที่แท้จริง" ไปตลอดสาย ตั้งแต่ query จนถึง Ok(result) — ถ้าตอนไหนใส่ชนิดผิด มันจะขึ้นแดงตั้งแต่ตอนพิมพ์ ไม่ใช่ตอนรัน

2 · async / await / Task — ใบรับฝากผลลัพธ์

ดู signature ของเมธอดใน controller คุณ — ทุกตัวยาวเหมือนกัน: 

public async Task<ActionResult<TodoItemDTO>> GetTodoItem(int id)
{
    var todo = await _context.TodoItems.FindAsync(id);
    ...
    return Ok(new TodoItemDTO(todo));
}
ชิ้นส่วนอ่านว่า
async"เมธอดนี้ทำงานแบบรอทีหลังได้" — เปิดให้ใช้ await ข้างใน
await"รอตรงนี้ แต่ปล่อยเธรดไปทำอย่างอื่นก่อน" — ไม่บล็อกทั้งแอป
Task<T>"ใบรับฝาก" ที่สัญญาว่าเดี๋ยวจะมีค่าชนิด T มาให้ทีหลัง

กฎเหล็ก 2 ข้อ:

① ถ้ามี await ต้องมี async ในเมธอดนั้นเสมอ
② ถ้าลืม await เมธอดจะ "รีบคืนใบรับฝาก" แล้วไปทำอย่างอื่นต่อ — ผลลัพธ์อาจยังไม่มาถึงตอนที่คุณใช้มัน เป็น bug คลาสสิกของมือใหม่

3 · Attributes [...] — ป้ายที่ framework เป็นคนอ่าน

[ApiController]                        // ป้าย: "คลาสนี้เป็น API controller จัดการ model binding ให้หน่อย"
[Route("api/[controller]")]           // ป้าย: "เส้นทางฐานของคลาสนี้คือ..." (บทที่ 1 เราเห็นแล้ว)
public class TodoItemsController : ControllerBase
{
    [HttpGet("{id}")]                  // ป้าย: "เมธอดนี้รับ GET /api/todoitems/{id}"
    [Required(ErrorMessage = "กรุณาระบุหัวข้องาน")]  // ป้าย validation (ใน DTO)
    ...
}

จุดสำคัญ: attributes ไม่ใช่คำสั่ง — มันคือ "โน้ตติดไว้" เฉยๆ ต้องมีใครสักคนมาอ่าน ซึ่งคนที่อ่านคือ ASP.NET Core เอง และแต่ละป้ายจะถูกอ่านใน คนละช่วงของ pipeline — [Route] ถูกอ่านตอน routing (บทที่ 1) ส่วน [Required] ถูกอ่านตอน model binding ซึ่ง Minimal API ไม่มีตัวนี้ให้ใช้เหมือนกัน — เรื่องนี้เจอกันเต็มๆ ในบทที่ 4

4 · Constructor + readonly — ประตูเดียวและข้อความกำกับ

private readonly TodoDb _context;          // ① ข้อความกำกับ: "เปลี่ยนไม่ได้หลังสร้าง"

public TodoItemsController(TodoDb context)  // ② ประตูเดียวที่ใช้สร้างคลาสนี้
{
    _context = context;                      // ③ DI เป็นคนยื่น context ใส่ประตูนี้ให้ (บทที่ 1)
}
  • private readonly — "ชนิดนี้ตั้งค่าครั้งเดียวตอนสร้าง ห้ามเปลี่ยนทีหลัง" ทำให้ _context ถูกแชร์ให้ทุกเมธอดในคลาสได้อย่างปลอดภัย
  • Constructor คือ "ประตูเดียว" — นี่แหละที่ DI ใช้ยัดของ (ต่อยอดจาก Aha! #2 ของบทที่ 1)

5 · เครื่องหมาย ? หลังชนิด — บอกตรงๆ ว่า "ค่าอาจว่าง"

public string? Title { get; set; }       // string ที่ยอมรับ null
public DateTime? DueDate { get; set; }    // DateTime ที่ยอมรับ null

โปรเจกต์คุณเปิด <Nullable>enable</Nullable> ไว้ใน .csproj แปลว่า compiler จะ เตือน คุณตอนใช้ค่าที่ "อาจเป็น null" ก่อนที่มันจะกลายเป็น NullReferenceException ตอนรัน — เห็นได้จากโค้ดคุณเองที่คอยเช็ค if (todo == null) ก่อนเสมอ นั่นคือระบบนี้ทำงานอยู่นั่นเอง

เล็กน้อยที่เหลือ (พอให้อ่านต่อได้)

เห็นในโค้ดอ่านว่า
var todos = ..."ให้ compiler เดาชนิดจากค่าขวาให้" — ไม่ใช่ dynamic นะ ยัง type-safe เต็มร้อย
{ get; set; }property — ช่องเก็บข้อมูลของคลาสที่อ่าน/เขียนได้
=> Set<TodoItem>();expression-bodied — เขียนเมธอดหนึ่งบรรทัดแบบกระชับ
new TodoItemDTO(todo)เรียก constructor ของ DTO เพื่อแปลง entity เป็นรูปทรงที่จะส่งออก

ลองของจริง (5 นาที)

  1. เปิด Controllers/TodoItemsController.cs
  2. อ่านออกเสียง signature ของ CreateTodoItem เป็นภาษาไทยทั้งบรรทัด 
    public async Task<ActionResult<TodoItemDTO>> CreateTodoItem(TodoItemDTO dto)
    ต้องแปลได้ประมาณ: "เมธอดนี้ทำงานแบบรอทีหลัง คืนใบรับฝากที่มี ActionResult ครอบ TodoItemDTO รับ TodoItemDTO ชื่อ dto เข้ามา"
  3. ชี้ทุก ? ในไฟล์ แล้วถามตัวเอง "ทำไมบรรทัดนี้ต้องยอมให้เป็น null?"
  4. Bonus: เปิด Data/TodoDb.cs แล้วอ่านบรรทัด DbSet<TodoItem> TodoItems => Set<TodoItem>(); ออกเสียงให้ได้

1 · Task<ActionResult<TodoItemDTO>> ใน signature บอกอะไรเรา?

Task<T> คือใบรับฝากที่สัญญาว่าเดี๋ยวจะมีค่าชนิด T มาให้ทีหลัง ส่วน async บอกว่าเมธอดนี้ "รอทีหลังได้" และ ActionResult<T> คือผลลัพธ์ HTTP ที่ครอบข้อมูลชนิด T ไว้ข้างใน

2 · บรรทัด private readonly TodoDb _context; หมายความว่าอะไร?

readonly หมายความว่าตั้งค่าได้ครั้งเดียวตอนสร้าง instance เท่านั้น หลังจากนั้นเปลี่ยนไม่ได้ — ทำให้ _context ถูกแชร์ให้ทุกเมธอดในคลาสอย่างปลอดภัย (ยังไม่ใช่ static นะ ยังเป็นของคนละ instance ต่อ request)

3 · [HttpGet("{id}")] คืออะไรในมุมมองของ C#?

attribute คือโน้ตที่ "เขียนทิ้งไว้" ไม่ใช่คำสั่ง — ASP.NET Core เป็นคนมาอ่าน [HttpGet("{id}")] ตอนขั้นตอน routing เพื่อจับคู่ GET /api/todoitems/{id} เข้ากับเมธอดนี้

4 · List<TodoItem> และ DbSet<TodoItem> ใช้แนวคิดอะไรร่วมกัน?

List<TodoItem> และ DbSet<TodoItem> ล้วนเป็น generics คือคลาสที่รับ "ชนิดข้อมูล" เป็นพารามิเตอร์ ข้อดีคือ compiler รู้ชนิดข้อมูลไปตลอดสาย และป้องกันการใส่ของผิดชนิดตั้งแต่ตอนพิมพ์ ไม่ใช่ตอนรัน

5 · public string? Title — เครื่องหมาย ? ทำให้เกิดอะไร?

เครื่องหมาย ? ทำให้เป็น nullable reference type — compiler จะเตือนคุณตอนใช้ค่าที่ "อาจเป็น null" ก่อนที่มันจะกลายเป็น NullReferenceException ตอนรัน โค้ดคุณที่เช็ค if (x == null) ก่อนเสมอคือระบบนี้ทำงานอยู่

6 · ทำไมหน้า ToListAsync() ต้องมี await นำหน้า?

await คือ "รอตรงนี้ แต่ปล่อยเธรดไปทำอย่างอื่นก่อน" — query SQL อาจกินเวลา จึงไม่ควรบล็อกเธรดที่กำลังรับ request อยู่ และถ้าลืม await โค้ดจะรีบวิ่งต่อทั้งที่ผลยังไม่มาถึง ซึ่งเป็น bug คลาสสิกของมือใหม่

สรุป

  • Generics <...> = ปลอกใส่ชนิด — compiler ตามชนิดได้ตลอดสาย
  • async/await/Task = ใบรับฝากผลลัพธ์ + รอแบบไม่บล็อกเธรด (มี await ต้องมี async)
  • Attributes = ป้ายโน้ตที่ framework เป็นคนอ่าน แต่ละป้ายถูกอ่านคนละช่วง pipeline
  • readonly + constructor = ข้อความ "เปลี่ยนไม่ได้" + ประตูเดียวที่ DI ใช้ยัดของ
  • ? = บอก compiler ตรงๆ ว่าค่าอาจว่าง เพื่อให้เตือนก่อนพังตอนรัน
